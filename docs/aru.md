# 在 Aru 里用黑胶播放器

接好以后：Aru 里的 AI 能搜歌、拆歌、读乐谱卡、给你点歌、帮播放器换外观；你在 Aru 里打开黑胶播放器放歌，点「一起听」，AI 就知道你听到哪一句了。

> **还没在 Aru 里从头到尾实测过**：MCP 用别的客户端测通了，Aru 的接法是照它的产品手册写的。哪一步跟你看到的界面对不上，请到 GitHub 提 Issue，附上截图（**遮住口令**）。

> **想让 AI 带着你装**：把这一页**全文复制**粘贴给它（别只发链接，国内常常打不开 GitHub 的原文）。最后一节「给带你装的 AI」是写给它的规矩。没装过 music-ears 的话，把 [windows.md](windows.md) 也一起复制给它。

## 要接两样东西

| | 给谁用 | 地址 |
|---|---|---|
| **MCP** | Aru 里的 AI | `https://你的子域名/mcp` |
| **网页应用** | 你自己（看、听） | `https://你的子域名/?key=口令` |

两样都指向你电脑上跑着的 `music-ears serve`，经 Cloudflare 隧道变成一个手机能打开的 HTTPS 地址。**不是放在 HTML 卡片里**：卡片是沙箱，连不了你的电脑、也存不住登录，播放器要当"网页应用"接。

## 开始之前

- music-ears 已经装好，`music-ears doctor` 最后一行是"没问题"（Windows 照 [windows.md](windows.md) 装）。
- 有一个自己的域名，已经交给 Cloudflare 管。
- 电脑上装了 cloudflared、建过隧道。**已经给 Aru Host 建过隧道的，直接用那一条**，不用新建。

下面的命令，Windows 在 music-ears 文件夹里打开 PowerShell 跑（命令前面加 `python `）；Mac / Linux 在终端里跑。

## 第 1 步：设一个口令

口令是一串随机字，有了它别人才进不来。生成一个：

```
python -c "import secrets; print(secrets.token_hex(16))"
```

会打印 32 个字母数字。**这串就是口令：别发给别人、别截图。**

把它写进设置文件，以后开 serve 就自动带上：

1. 打开文件夹 `%USERPROFILE%\.config\music-ears`（Windows 在资源管理器地址栏输入这串回车；Mac / Linux 是 `~/.config/music-ears`）。提示不存在就先建这两层文件夹：`.config`、`music-ears`。
2. 新建一个 `config.json`（Windows 注意别变成 `config.json.txt`：资源管理器"查看"里勾上"文件扩展名"）。已经有这个文件的，在最外层大括号里加 `"serve"` 那一项就行。
3. 内容写：

```json
{ "serve": { "token": "刚才那串口令" } }
```

## 第 2 步：开播放器

```
music-ears serve
```

看到 `黑胶播放器：http://127.0.0.1:8790/?key=口令` 就开好了。**这个窗口一直开着**，关了 AI 和播放器就都连不上了。

在电脑浏览器里打开 `http://127.0.0.1:8790/?key=你的口令`，能看到播放器就对了。

## 第 3 步：在隧道里加一个子域名

1. 打开 Cloudflare 后台 → Zero Trust → Networks → Tunnels，点你在用的那条隧道的名字（旧界面是右边的 Configure / 编辑）。
2. 找到 Public Hostname（公共主机名）→ Add a public hostname。
3. 填：
   - Subdomain：`ears`（随便起，下面都用 `ears` 举例）
   - Domain：选你的域名
   - Service：Type 选 `HTTP`，URL 填 `localhost:8790`（**是 http，不是 https**）
4. 保存。等一分钟，手机浏览器打开 `https://ears.你的域名/?key=你的口令`，看到播放器就通了。

> 打不开：先看第 2 步那个窗口还开着没有；再看 Service 是不是写成了 https（会报 502）。不带 `?key=` 打开会看到"要口令"，这是对的。

## 第 4 步：在 Aru 里接 MCP

总设置 → 连接 → MCP → 添加远程服务：

1. 类型选 **streamable HTTP**，地址填 `https://ears.你的域名/mcp`。
2. 认证选 **Header**，加一行：名字 `Authorization`，值 `Bearer 你的口令`（Bearer 和口令之间一个空格）。
   - 找不到填 Header 的地方，就把地址写成 `https://ears.你的域名/mcp?key=你的口令`，效果一样。
3. 测试连接。成功的话能看到 11 个工具（`search_song`、`play`、`now_playing`、`set_skin` 等）。
4. **启用**这个服务器 → **允许你的协作者使用** → 在对话的**工具箱里打开 MCP 开关**。三处都要开，少一处 AI 就用不了。

## 第 5 步：在 Aru 里接播放器

总设置 → 应用与连接 → 连接网页应用：

1. 地址填 `https://ears.你的域名/?key=你的口令`（凭据方式选"持续 URL token"或者直接带在地址里都行）。
2. 装好以后，把它放进对话里的 Apps 启动器，或者协作者桌面 / Dock，方便打开。

第一次打开时口令会记住，之后不用再带。

## 第 6 步：试一遍

按顺序试，哪一步不行就停在那一步看下面的"不行怎么办"：

1. **问 AI**：「用 music-ears 搜一下《晴天》」→ 它应该列出几首，带编号。
2. **点歌**：「给我点一首你喜欢的歌」→ 打开播放器，屏幕下方冒出它说的话，那首排在下一首（什么都没放时直接开始放）。
3. **拆卡**：在播放器里给一首歌点「⋯」→「拆乐谱卡」，屏幕上方出现进度条，一首 4 分钟的歌约 8 分钟。
4. **一起听**：拆好以后点「⋯」→「一起听」，放一会儿，问 AI「我们听到哪了？」→ 它应该说出正在唱的那句。
5. **换外观**：「把播放器换成樱花粉」→ 几秒内播放器变色。不喜欢就说「换回默认」。

## 不行怎么办

| 看到什么 | 多半是 |
|---|---|
| Aru 测试连接失败 | 第 2 步的窗口关了；或者地址少了 `/mcp`；或者口令（Header 里的 Bearer 那串）抄错了 |
| 连上了，但 AI 说没有这个工具 | 第 4 步的三个开关没开全（启用、允许协作者、工具箱 MCP） |
| 播放器打开是"要口令" | 地址后面没带 `?key=口令`，或者口令抄错 |
| AI 点的歌没出现 | 播放器没开着（打开以后半小时内点的歌都会补上）；或者开着的不是同一个地址 |
| 「我们听到哪了」AI 说没在一起听 | 要在播放器里点「一起听」，光放歌不算；没拆过的歌要先拆 |
| 拆卡失败 | 在电脑上跑 `music-ears doctor` 看哪项是 ✗ |
| 切回对话后歌停了 | Aru 里的网页切到后台可能不让出声。可以改在手机 Safari 里打开同一个播放器地址放歌，一起听照样算 |

## 口令和安全

- 口令等于钥匙：带口令的地址别发到群里、别截图。
- 不想让别人用了、或者口令可能漏了：照第 1 步换一串新的，重开 `music-ears serve`，再把 Aru 里两处的口令都换掉。旧的立刻失效。
- 音乐由你的手机直接从网易云取，不经过 music-ears，也不会被存下来。

## 给带你装的 AI

如果你是 AI，正在照这一页带一个人把 music-ears 接进 Aru，请照下面做：

**先问清楚再开始**
- 先问：music-ears 装好没有，`music-ears doctor`（Windows 是 `python music-ears doctor`）最后一行是不是"没问题，可以用了"。没装或者有 ✗，先照 windows.md 装好，别跳到这一页的第 1 步。
- 再问：用的是 Windows 还是 Mac；有没有自己的域名交给了 Cloudflare；电脑上有没有已经在跑的 Cloudflare 隧道（比如给 Aru Host 建的那条）。没有域名或隧道的，这一页做不下去，先如实告诉对方。

**一次只带一步**
- 一步一步来：说清楚这一步做什么、为什么，等对方说做好了、并且达到下面的"做好了的样子"，再往下。不要一口气把几步全丢给对方。
- 对方多半没用过命令行：命令要整段给，说清楚在哪个窗口里粘贴、粘贴后按回车；窗口要一直开着的（第 2 步）要特别提醒。

**口令：绝不进对话**
- 不向对方要口令，不让对方把口令、`config.json` 的内容、带 `?key=` 的地址、Header 的值贴进对话或者念出来。哪怕是为了帮忙核对也不要。
- 要看截图时，先提醒对方把口令遮住（打码或者裁掉）。万一对方已经发出来了，告诉对方照「口令和安全」一节换一串新的。
- 要核对口令有没有抄错，让对方自己对比（比如"config.json 里那串和 Aru 里填的那串，前四个、后四个字一样吗"），不要让对方发给你。

**界面对不上时别编**
- Cloudflare 和 Aru 的界面会改版，这一页写的按钮名可能对不上。对不上时，请对方截图（遮住口令）或者描述屏幕上看到了哪些字，照着实际看到的带，不要凭印象编按钮名和菜单位置。
- 不确定的就说不确定。

**每一步做好了的样子**
- 第 1 步：`config.json` 存好了，扩展名真的是 `.json`（不是 `.json.txt`）。
- 第 2 步：窗口里出现「黑胶播放器：http://127.0.0.1:8790/…」，电脑浏览器带上口令打开能看到播放器。
- 第 3 步：手机浏览器打开 `https://子域名/?key=口令` 能看到播放器；不带 `?key=` 打开是"要口令"。
- 第 4 步：Aru 测试连接成功，能看到 11 个工具；三个开关（启用、允许协作者、工具箱 MCP）都开了。
- 第 5 步：在 Aru 里能打开播放器。
- 第 6 步：五项都试过——搜到歌、点的歌出现在播放器里、拆卡有进度条、一起听时 AI 说得出正在唱的那句、换外观几秒内变色。

**卡住了**
- 先对照「不行怎么办」那张表。
- 第 4 步连不上时，先回去确认第 3 步（手机浏览器能打开播放器）真的通了，再查 MCP 的地址和 Header。
- 实在不行，请对方到 GitHub 提 Issue，附上截图和 doctor 的输出（都遮住口令）。
